# USC OSM pipeline dataset

Exported from routingc's `models/routing/osm_build/map.osm` via its existing
`upc_graph.py` trimmed graph. Attribution: OpenStreetMap contributors, ODbL;
see https://www.openstreetmap.org/copyright . This is a derived simulation
network, not a complete or surveyed USC accessibility map.

The source has 104 nodes, 202 walkways and 23 buildings. The shared dataset has
832 nodes and 930 segments. Geometry vertices become graph nodes so pedestrians
follow curved paths. Every original walkway is preserved, including parallel
walkways: edge-specific intermediate nodes make node routes unambiguous.
Segment distances sum to each source walkway's original length. Building
entrance order is preserved in buildings.json. source_edges.json maps all
exported segments back to original (u,v,key) edges for audit/reconstruction.
Coordinates are projected meters translated to a local origin; source CRS
and offset are recorded in dataset.json.

## Explicit simulation assumptions

- Shade is generated by Environment from walkway direction, position, and its
  daily shade profiles. Building profiles change with time; open and tree-lined
  profiles remain constant. These are assumptions, not measured shadows.
- There is no fixed shade schedule. The manifest names `source_edges.json` so
  Environment assigns one profile per original walkway, shared by its segments.
- Weather comes from the existing Environment scenario, not live observations.
- SIM_M1/SIM_M2 are hypothetical misters at Leavey/SGM; SIM_S1/SIM_S2 are
  hypothetical signals at high-degree junctions, not real installed hardware.
- Generic pedestrian traversability is assumed; accessibility is not surveyed.
- Most building entrances are inferred by the original routingc builder.

Do not apply campus_50's actuator positions or shade IDs to this map. Pass this
dataset's folder as `context["dataset_dir"]` when calling Environment so its
original-walkway grouping is used; the pipeline and standalone runner do this.
Without it, automatic shade is assigned independently to each graph segment.

## Optional misting layouts

`python main.py --misting-count 0|4|6|10` selects a runtime overlay from
`misting_scenarios.json` (replace the alternatives with a single number).
Four uses placements 1-4, six uses 1-6, and ten uses 1-10, matching the proposed
comparison maps. The first two retain the original mister locations; added
locations favor junctions on shortest paths between building entrances, with
spatial separation. This heuristic is not based on measured pedestrian demand
or a proven optimal layout. All use the environment's 10 m default radius.
Zero removes all misters. Signals remain identical across scenarios, and the
base dataset files are never rewritten. Omit the option to retain the original
two misters. Run metadata records selected placements in every stage's output.

## Rebuild (optional development dependencies)

From the repository root:

```sh
python -m pip install -r models/routing/osm_build/requirements.txt
python models/routing/osm_build/upc_graph.py
python models/routing/osm_build/export_pipeline.py
```

The builder writes GraphML/building lookups beside its scripts in `osm_build`;
the exporter writes to `dataset/usc_osm_trimmed`. Standalone demos now live in
`models/routing/demo`; see its README for commands.
The exported JSON files are sufficient for the main pipeline; it does not
import OSMnx, plotting, or the standalone prototype simulator.
